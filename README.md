# SR 测试项目

StarRail-OneDragon 主仓的**独立测试仓**(主仓 gitignore,单独提交)。当前主要覆盖
货币战争(`currency_war`)玩法:单元/单帧锁、fixture 驱动的 op 流程测试、sim 检查器
与账本契约。测试纪律见下方「测试纪律」,写入新测试前必读。

## 快速开始

从**主仓根目录**运行(测试内的 `sys.path` 定位依赖仓根相对关系):

```shell
uv run pytest sr-od-test/ -m "not slow"   # 全量(标准,串行;排除慢桶)
uv run pytest sr-od-test/test/sr_od/app/currency_war -m "not slow"  # 快速层=CW 域目录直跑
uv run pytest sr-od-test/test/sr_od/app/currency_war/test_cw_merge.py  # 单文件
```

- **慢桶**:`slow_marks.txt` 登记单条实测 ≥2s 的用例;快速层用 `-m "not slow"` 跳过,
  全量不过滤。新增慢用例须同步登记。
- **快速层 = CW 域目录直跑**(2026-09-03 起,废手工清单 `cw_quick.txt`):目录即磁盘真相,
  零维护零漂移。教训:手工清单与磁盘漂移 44 文件(新文件漏登记)才废除;新增测试放对
  目录即自动入层,不再维护任何文件清单。

## 测试纪律(硬规则)

### 隔离与副作用

1. **`test_context` 是 session 级共享**(conftest):改其属性(`run_context`/`controller` 等)一律
   `monkeypatch.setattr`(自动还原);裸赋值会污染后续**别的测试文件**(单跑必过/全量必挂的假
   flaky),conftest 有 autouse 守卫(警告+还原),但守卫不是写裸赋值的许可。
2. **测试不写真实 `.debug/` 路径**:落盘一律 `tmp_path` 或 monkeypatch 重定向目标模块的
   `_DIR` 常量;`finally` 还原动过的外部状态(文件备份-恢复、flag 清理)。已有的:conftest
   autouse 机检层 `_isolate_debug_images` 把测试进程内 `debug_utils.save_debug_image` 恒重定向
   tmp_path(op 框架异常 handler 的自动存图也在内);其它落盘点照此办理。
3. **测试不发真实网络请求**:凡被测链路会触网(如配置初始化拉代理地址),在测试入口
   mock 掉——网络慢且引入不确定性(断网/代理变化 = 假 flaky)。
   已有的:conftest 短路 `ghproxy_service.update_proxy_url`;新增触网路径照此办理。
4. **测试隔离「整条副作用链」,生产副作用「缺省关+显式接通」**(全集假红实证:
   安灯测试沿调用链惰性触发真停线 → gc 扫描命中 session 级 ctx 写停机位+真实
   flag,monkeypatch 不辖此副作用 → 后续 execute 全撞刹车):
   - 被测生产路径含**模块级全局**(handler/闩锁/计数器/缓存)时,setup 必须
     一并桩化/清空——patch 清单来自「沿调用链 grep 模块全局」,不来自「我
     调了什么」;
   - 生产模块的对外副作用(停机/写 flag/截图/外部 IO)一律 `set_xxx_handler`
     注册模式,**缺省 None=不做**,生产在启动点显式接通;禁新写「缺省 None→
     惰性 import 真实现」(判例:L0 安灯槽注释,`cw_telemetry._L0_ANDON_HANDLER`);
   - conftest 已有守卫:整对象替换(`_guard_shared_ctx`)+ 运行残留
     (`run_context.last_run_result`,警告+自动复位)——守卫是防线不是许可,
     漏桩仍要在源头修。

### op 流程测试

5. **fixture 驱动的 op 流程测试**用 `test/harness/fixture_controller.py`(`FixtureController`
   + `WatchdogOperationMixin` + `enter_running_state`/`reset_running_state`);运行态前置/复位
   已封装在 helper 里,别手写 `_run_state` 裸赋值。
6. **op 流程测试的 `execute()` 必须包 `fast_sleep()`**(harness 提供):mock 画面瞬间切换,
   框架的轮间/点击前等待(`pre_delay`/`_after_round_wait`)纯属空等。
   用法 `with fast_sleep(): result = op.execute()`。

### 锁的写法:语义、出处与形态

7. **锁的存在性纪律**(写锁/改锁/删锁四判据):
   - **出处落锁内,且必须是持久索引**:锁的设计出处写在 docstring/注释(不是
     commit message),取值为 ADR-NNNN / 文档路径+节名 / 纯语义描述(如
     「25 局实机 HP 轨迹校准」)。会话局部编号(轮次号 / review rN / D-xxx 等)
     不构成出处——它们在 docs 树里检索不到,等于没写。批报告类出处(`.debug/`
     路径)可暂记,但批报告属易失产物,后续批须回填 ADR/文档指针。
   - **「登记门」与「快照锁」分形态给容差**:强迫显式登记语义的锁(如 registry
     字段面期望表:增删字段/改默认/改类型=红且点名字段)允许高频被动更新——
     它的高换手正是反机械跟绿机制的运转证据;与之相对,锁统计数值/不可读
     哈希差的纯快照锁才是 change-detector 陷阱。判别问句:**「这把锁红的时候,
     我知道该登记什么语义吗?」**知道=登记门,照常跟绿;不知道=快照陷阱,
     先重推语义再动。
   - **改锁值必须同步锁内旧表述**:断言值与 docstring/注释写的是同一事实,
     出现两个版本 = 机械跟绿已发生的现场证据。跟绿时注释不同步与跟绿本身
     同罪,改锁批必查。
   - **重复断言构成删/并理由,「老」不构成**:同一断言出现在两文件,或同文件
     两锁辖同一事实 → 择一保留、另一处删或留指针注释。「这锁老」不是删锁
     理由;判删必须引设计文档证被锁行为已非设计意图。择一保留取**超集**
     (负例/边界更全者);判「重复」必须亲读两处证实覆盖面,证实不了的
     不删(2026-09-03 瘦身批实测:亲读驳回 2 处审计误报)。
8. **源码锁三档判据**:
   - **实现形状锁 = 禁**:断言活代码的字面量/缩进/禁子串/变量名/调用行序——
      合法重构即假红(判例:断言某模块属性含某行代码、含缩进的换行字面量、
      用 `.index()` 比两行先后);**肯定性在场锁同族 = 禁**(判例:断言
      `'SHOP_OPEN_ANIM_S' in src`——常量名/标识符必须出现在源码中,不验证
      任何行为,实现演进时机械跟绿;2026-09-02 用户质疑成立:同一断言因口径
      变更连跟三次,零拦截价值 = 实现的影子);
   - **接线存在性烟雾 = 容忍**(至多 1 条,docstring 须引用失守事故):断言某
      调用点存在,防证据链/防线静默脱落;该 op 有了 fixture harness 就应
      升级为行为锁;
   - **顺序即语义 = 容忍但记债**:断言的是行为边界而非行存在(判例:对账
      补拷必须在 decide_prep 之后——提前拷=改决策行为),无更便宜观测点时
      保留;重构该处代码时同步改写锁。
   - **合法的源码扫描**:①墓碑扫描——断言退役符号无残留(带变异自检更佳);
      ②依赖方向/单一源守卫——分层禁直依、判据禁第二源;③包/注册表布局守卫
      (墓碑与肯定性在场锁的区别:墓碑 = 「否定式 + 退役背书」,影子 = 「肯定式 + 无独立语义」。)
9. **数值锁必须推导锚定**:期望值从单一源推导式现算(registry 常量/证明集
    公式),不得手抄常数。正例:血警阈值断言 `emergency_hp ∈ (2×L_c(rung2),
    rebirth_floor+L_c)`,L_c 从 registry 拟合常数现算;反例:断言评分栈等于
    手抄常数且自供「漂移即红」——红不含语义=change-detector。
10. **被测代码必须被调用,禁自抄复刻**:测试体不得复刻被测逻辑再断言自己抄的
    结果(判例:难度读链测试曾重写「live 优先于 session」的 if/else——生产
    翻转块改坏它照样绿,已删)。识别特征:删掉被测函数后它依然绿。
11. **锁契约不锁分布,重结果一次复用**:
    - 断言「输出结构/范围/回显」而非统计数值——锁分布数值 = change-detector 陷阱,
      任何合法改动必红(判例:`test_batch_stats_shape` 只锁形状;smoke 的 docstring 同款约定);
    - 同一份昂贵计算在**同一次测试运行内只算一次**,多条断言共享结果,逐条各算纯浪费;
    - 昂贵的**可序列化中间产物**(逐局终值等)优先从已有产物(账本/报告)提取,
      别为断言再跑一遍。
12. **批量/循环模拟的 n 取「断言成立的最小值」**:断言全是形状检查时,更小的 n 与更大的
    n 等价;更大的样本量属于 sim A/B 日常工作流,不该由单元测试承担。
    同理:不落盘选项(`ledger=False`)优先于默认落盘。
    **续(2026-09-03):存在性断言的种子扫面,探底后固化「显式命中种子列表」**——
    扫面循环的真实需求是「命中的种子」,不是「跑满 N 个种子赌命中」。实测探底
    (逐种子 spy 记录哪些命中)后,把命中种子的最小代表集写为显式常量,注释里
    带探针记录(扫描窗/命中率/各种子形态),非命中种子不再付每次的运行成本。
    判例:补给重掷链 12 种子(9 命中)→ 显式 (0,4,8) 三形态代表,call 5.28s→1.38s。
    边界:①断言若是分布统计(n 本身是语义)则扫面保留;②种子列表=校准锚同责——
    引擎改动位移 RNG 消费致列表失准时测试红,处理=重跑探针更新列表,不是机械跟绿;
    ③列表失准的红必须可行动(报错信息指向「重跑探针」,不是裸 assert)。
13. **生产供给字段的锁必经生产链路,禁只直调注入**(与第 7 条「锁的存在性
    纪律」并列;教训:连败供给直调锁绿了两轮,生产链断了两轮——
    写点只活在胜轮通道,败局半环无人看守):
    - 凡被测字段属「生产供给」(生产采集链/执行层写、策略只读的输入,
      如 `session.last_streak`/`cw_paid_refreshes`),其回归锁**必须至少
      一条经生产调用链**触发写点(battle_loop 级 harness / sim 引擎装配),
      不得只直调策略钩子或手工注入 session 值;
    - 直调锁只证明「消费半环」对输入的反应;「供给半环」(生产真的会写
      这个字段、写点没脱落)由输入供给合同表
      (`cw3/knowledge/input_contract.py`)+ 守卫
      (`test_cw3_input_contract.py`)看守,新字段先登记合同再写消费代码;
    - 判别问句:**「生产哪一行代码坏了,这把锁会红吗?」**答不出 = 锁只
      罩了半环,补生产链路锁或合同写点锚。
14. **写新锁的落点与形状**:
    - 新锁写进所属机制的**主题文件**(如 `test_cw_merge.py`/`test_cw_plane_p2.py`/
      `test_cw_blood_crisis.py`),禁新建一轮一修复命名的文件——主题文件按机制
      归并,同名事实的测试以来源前缀区分,别再长回来;
    - 已知 wart(docstring 自认「解耦时会改」的行为)不得立锁,登记挂账替代;
    - 同机制家族共用构造器,放主题文件头部;跨文件的复制夹具是漂移源头。

### 死锁形态与输入密闭(2026-09-03 瘦身批沉淀)

18. **死锁形态禁令**(瘦身批最常删五类,写时禁、评审删;处置前先过
    第 7 条判别问句——答得出语义的改造为行为锁/登记门,答不出的删):
    - 恒真断言与空壳:`assert X or True`、只 print 不断言、空函数体、
      `skip+pass` 死占位;
    - **构造/字段透传断言**:构造对象后逐字段 assert 赋值——dataclass 行为,
      不测我们代码(2026-09-03 攻击性排查实证:AreaMatchDetail 构造 ×3)。
      例外 = 断言值本身是**跨进程契约**(如 `AreaType 'text'/'template'` 是
      analyze_screen 输出契约)——判别问句:**「这个值改了,谁会坏?」**
      答得出具体外部消费者=契约锁保留;答不出=透传装饰品;
    - 子集断言:同文件后一条测试的前置真子集(判例:stop reason 记录单测
      ⊂ 幂等保首测——幂等测断言面完整覆盖它);
    - **docstring 语义 ≠ 断言面**(判例:session_counters 声称锁「环入口
      清零」实际只断言新构造默认值——重置缺失根本不会红)。自检问句:
      **「这条断言红了,docstring 说的那个故障真的发生了吗?」**答不是=删;
    - **xfail 毯子纪律**:整模块/永久 xfail 必须带到期条件,或用
      `strict=True` 让意外转绿报警(正例:test_id_mark 错档 fixture 修复
      转XPASS会响;反例:cal_pos 双变体 xfail 一个月,13.5s/次且无法区分
      已知漂移与新增破坏,连装载器 bug 都被毯子盖住);
    - **xfail/装饰器标记漂移**:标记 reason 与测试体语义无关即为装饰器
      漂移(判例:reason 讲 star-aware 战力计价缺口、测试体测购买经验
      取整,实跑 XPASS)——XPASS 即摘标记复核:测试体有独立语义则保留
      摘标,无则随删;
    - 自抄复刻(第 10 条)的现场证据:docstring 出现「复刻/复制内联条件/
      同条件复制」自供;
    - 断言文档含特定措辞:文档措辞改即红且无可登记语义 = 快照锁;
    - `hasattr`/标识符在场的肯定性烟雾超出「至多 1 条」容差(第 8 条);
    - 混合锁拆解手法:否定墓碑(退役背书)与依赖方向守卫**保留**,
      肯定式字面删除(判例:w536 接线锁群收敛为墓碑+单一源守卫两角)。
19. **测试输入密闭**:断言依据一律来自测试自造的合成输入(tmp_path/合成
    语料/monkeypatch 桩)或提交进仓的数据文件;**禁读 `.debug/` 等本地
    易失产物当断言锚**(现有纪律只禁写,本条补读侧)。消费「会被本地
    再生管线重写的数据文件」(如 cw_delta_pool_data)只做进程内自洽比较,
    禁「import 时状态 vs 执行时现算」的跨时间点比较(判例:池再生锁与
    实机局终自动再生管线竞态假红,已密闭化为合成 3 行语料+写 tmp_path)。
20. **静态扫描测试的存废判据**:测试里跑全仓/整包源码扫描前,先判锁的对象——
    - **语言通用约定**(任何 Python 项目同款,IDE/lint/typing 有现成检查,
      如「调用参数名 ∈ 被调签名」)→ **删或转 lint 工具**,不进测试网
      (判例:kwarg 全仓审计删除,防线转代码规范+review——通用约定
      reviewer 看签名就能抓,测试只付每次全量 5.6s);
    - **项目架构裁决**(本项目自己决定的事,如桶依赖矩阵/退役符号禁回流/
      分层 import 禁令——工具不知道你的桶,reviewer 记不住矩阵)→ **留**,
      测试是唯一会红的载体;附「盲区自检」(新文件落错位置时守卫必须
      能起诉,禁假绿,判例:package_layout 守卫 2)。

## 写锁/评审四问(进门自检)

1. 这条锁红的时候,我知道该登记什么语义吗?(答不出=快照陷阱,见第 7 条)
2. 什么**真实错误**会杀了它?答不出具体错误场景=装饰品(见第 10 条)。
3. 这条事实是否已有别的锁?同层有=删;跨层要说明新增价值(接线/端到端)。
4. 这条锁值多少毫秒?说不出拦截价值就撑不起运行成本(见第 15 条)。

## 存量清理工作法(大扫除怎么组织)

0. **动刀前置检查**:多批并行期,编辑任何文件前先 `git diff <file>` 确认
   无他批未提交改动(实证教训:prep_director 混入并行批 ~170 行,仅查
   mtime 不够);有混入则只判不刀,判决留档待其落地后执行;
1. **机械扫描定位候选**:`inspect.getsource`/`time.sleep`/`or True`/
   重复函数名/手抄常数表,一次扫出全仓候选清单;
2. **逐条亲读核验**:扫描与审计建议 ≠ 执行依据;判「重复」证实不了
   覆盖面的不删,判「违例」读不出条文依据的不动——误报是常态;
3. **五种处置**:删(有纪律依据)/并入主题文件/改写(降 n、形状锁改
   行为锁、裸赋值改 monkeypatch)/记债(顺序即语义等容忍档,写明背书)/
   驳回(误报,记录理由);
4. **小批验证**:每文件手术后单文件跑绿;每批收尾受影响域全跑;
5. **工单记账**:处置清单落盘 checklist(处置+依据+核验结论),跨会话
   可续,防「做到一半不知道到哪」(判例:`.debug/temp/test_slim_backlog.md`,
   不入 git,用完即弃)。
6. **批号/桶标 ≠ 锁龄,处置前按语义重推**(2026-09-03 歼击战判例):
   r420/r363 批号审计文件重推后锁对象仍是现行设计=判留;w443 整文件被
   错挂旧核基线标记(该标记已废止)而锁对象现役三处消费=守卫哑火。冻结桶
   (旧核基线桶[已废止]/慢桶)巡检时必须核对锁对象活性——打标前 grep 消费方,
   已挂标的定期重验;错挂=摘标复活而非删除(复活判例:w443 双口径 5 passed)。
7. **死指针=覆盖缺口哨**:docstring/注释指向不存在的测试文件时,必须
   核查该语义现由谁辖——可能是独家覆盖裸奔(判例:w633 塌缩带归零锁
   自称并入目标实为独家看守;w628 哨兵「并入目标」从未存在,语义裸奔
   至复活)。查实无人辖的登记复活待办,不是顺手删注释了事。
8. **删并的并入目标必须存在;有独家语义/夹具可入仓的优先复活**:删并前
   grep 全目录确认并入目标在仓且覆盖面属实;独家语义+夹具可迁的处置=
   迁移复活(判例:identity_funnel 真帧入仓复活 SIFT 5 牌真值锁)而非删除。
9. **计数对账以 collect-only 实测为准**:同名 def 重复定义后定义遮蔽前
   定义(w443 静态 20 def 实收 5),参数化放大静态数(1 def 收 48);
   批次派单与验收对账一律 `--collect-only` 实测,静态 def 计数只作粗筛。

## 运行机制与性能

- **OCR 结果持久缓存**(`.pytest_cache/d/ocr_memo/`,conftest 内置):内容哈希
  + 模型指纹键控,跨会话复用同一 fixture 的推理结果;模型更新自动失效,
  `pytest --cache-clear` 一键清;CI 恒冷路径,无收益也无成本。
- **OCR 设备跟随本地 `config/model.yml` 的 `ocr_use_gpu`**(测试 ctx 继承):
  本机开 DirectML 更快,两种设备文本集一致;无 DML 的环境(CI)自动回退纯
  CPU,不会崩。注意:开 GPU 时若同机还有实机局/MCP server 在用 DML,会互相争用。
- **测试进程默认不写日志文件**(conftest 日志隔离):pytest 进程退出共享日志
  写入方集合(框架 logger 挂 NullHandler 占位),从源头消掉与并行的 sim 批/
  regen 进程的日志轮转竞态。排查具体测试要看框架日志时,设 `SR_TEST_LOG_FILE=1`
  走旧路径 `.log/test.log`(配合下一行降噪改 INFO)。
- **sim 日志已降噪**(conftest 模块级 framework log INFO→WARNING):sim 逐决策
  INFO 会一轮全量写巨大 test.log。排查具体测试时,设 `SR_TEST_LOG_FILE=1`
  并临时把 conftest 里 `setLevel(logging.WARNING)` 改回 INFO 重跑。
- conftest 已内置两项 session 级优化:初始化时短路 `ghproxy_service.update_proxy_url`
  (避免真实网络请求);`ocr_service` 包内容哈希 memo(同一 fixture 图跨文件只推理一次)。
