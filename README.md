# SR 测试项目

StarRail-OneDragon 主仓的**独立测试仓**（主仓 gitignore，单独提交），覆盖框架与业务的单元测试和 fixture 驱动的 op 流程测试。

**本文件是测试纪律的单一源**，判据在此展开成可执行细则；主仓 `AGENTS.md`「10.测试规范」是这里的常驻摘要（只保留第一原则与高频违错）。

## 快速开始

从**主仓根目录**运行（测试内的 `sys.path` 定位依赖仓根相对关系）：

```shell
uv run pytest sr-od-test/ -m "not slow"    # 标准全量（串行，排除慢桶）
uv run pytest sr-od-test/                  # 含慢桶（慢桶不可丢，定期跑）
uv run pytest sr-od-test/test/sr_od/backend/test_mcp_app.py   # 单文件示例
```

**慢桶**：单条实测 ≥2s 的用例，把 nodeid 后缀（`文件名::类::测试`）登记进 `slow_marks.txt`，conftest 自动打 slow 标记。维护命令：

```shell
uv run pytest sr-od-test/ -q --durations=300 --durations-min=1.0   # 按耗时巡检回填
```

已提速到 2s 以下的及时摘牌——否则快速集白跳过、覆盖白丢。

## 目录结构与环境

```
sr-od-test/
├── slow_marks.txt                      # 慢桶名单（逐行一条 nodeid 后缀）
├── test/
│   ├── conftest.py                     # 全部公共设施：夹具与隔离守卫 + 慢桶标记、收集期守卫（见下）
│   ├── harness/fixture_controller.py   # op 流程测试 harness（见下）
│   ├── one_dragon/                     # 框架层测试
│   └── sr_od/                          # 业务测试（backend / operations / application …）
└── README.md
```

- Python 3.11 + uv（依赖随主仓 `--group dev`）。
- PyCharm 需把本目录标记为 **Test Sources Root**，否则 `from test.conftest import ...` 无法解析。

## 测试基础设施（已内置，写测试前先知道）

**`test/conftest.py`**（自动加载，全部公共设施都在这一个文件）：

- 慢桶标记：按 `slow_marks.txt` 给命中用例打 slow 标记，`-m "not slow"` / `-m slow` 分层选摘。
- 收集期守卫：检测模块级 `logging.disable` 泄漏（会静默饿死其他测试的日志断言，整轮报错）；预检 OCR 模型文件在位（模型目录不入 git，被误清理时给出恢复指引，而不是让几百条测试炸在深处）。
- `test_context`：全测试共用的同一个 `SrTestContext`。改它的属性必须用 `monkeypatch.setattr`（自动还原）；裸赋值会污染后续别的测试文件——「单跑能过、全量必挂」的假随机失败多来自这。另有守卫自动警告并还原裸赋值与运行残留，但守卫是防线不是许可。
- 外连阻断：测试进程的外部连接被统一拦截，不发真实网络请求；新增触网链路无需各自 mock。
- 落盘重定向：`debug_utils.save_debug_image` 一律重定向到 `tmp_path`，测试不写真实 `.debug/`。
- OCR 结果缓存：同一张图（内容哈希键控）只推理一次，结果跨测试文件复用，另有磁盘层（pytest cache 目录）跨会话复用；`pytest --cache-clear` 一键清。
- 日志隔离：测试进程默认不写日志文件（避免与并行进程的日志轮转竞态）。要看框架日志排查时，设 `SR_TEST_LOG_FILE=1` 走旧路径，并临时把 conftest 里的日志级别改回 INFO。
- 其他隔离：窗口互斥锁目录、停机 flag 通道等重定向到临时位置，测试间互不残留。

**`test/harness/fixture_controller.py`**（op / app 流程测试 harness）：

- `FixtureController`：假游戏控制器，按「剧本」演流程——每步给哪张存档截图当画面、点击落在指定 area 内就推进到下一步；所有点击/输入有记录供断言。
- `WatchdogOperationMixin`：轮次超限自动停，防测试自身死循环。
- `enter_running_state` / `reset_running_state`：运行态前置与复位（别手改 `_run_state` 字段）。
- `fast_sleep()`：把框架的轮次间/点击前等待变成空等（上下文管理器，包住 `execute()` 或直调的节点方法）。**不包就会真睡**——框架的等待是给真机等画面用的，mock 画面瞬间切换，等待纯属空等。

## 测试纪律

### 第一原则：测试只覆盖核心内容，极致运行效率

自动化没法靠人肉回归，测试就是质量底线——但**只测核心**。每条测试锁的都是「这段代码应该怎么表现」，来源只有两个：

- **新功能**：锁设计约定——按设计文档应该怎么表现（关键路径 + 设计明确处理的边界），测试随功能一起写，就是可执行的设计说明；设计里没约定的行为不要瞎测。
- **存量功能**：锁真实故障——出过的事故、真实可能发生且后果严重的故障形态（卡死一条龙、登录失败、认错画面）。

写不出锁的期望表现的，一律不写：琐碎逻辑、构造完对象逐字段断言、语言自带保证、与其他测试重复的内容。由此：

1. **测试要少**：两条测同一件事 = 冗余，能合并就合并。测试越堆越多，真正的失败越容易被淹没——漏看的红等于没有测试。
2. **慢计算与贵加载只算一次**：OCR、识别、模拟这类慢计算，以及大文件解析、整帧解码这类贵加载，同一次运行只跑一次，结果给所有断言共用——同文件多处各读各的 = 重复付钱。
3. **串行为准**，默认不用并行测试。
4. **慢速集**：单条实测 ≥2s 登记进 `slow_marks.txt`，快速集带 `-m "not slow"` 跳过。

### 写测试

1. **主题文件**：测试放进所属机制的文件，按机制归并；禁新建「一轮一修复」命名的文件（round / 批次号 / 日期命名）。
2. **docstring 写期望表现 + 出处**：出处用持久索引（ADR 编号 / 文档路径 + 节名 / 语义描述，如「25 局实机 HP 轨迹校准」）；轮次号、review 编号等会话局部标识符不算出处——在文档树里检索不到，等于没写。
3. **断言结果的结构与文案**（返回哪些字段、状态消息说什么），不断言会随正常调整变动的统计数值；数值型期望从单一来源现算（引用常量 / 公式），不手抄常数。
4. **「这个值是生产代码生成的」也要有测试盖住**：mock / 手工塞值只测到「拿到值之后怎么用」这一半；「这个值在生产代码哪里算出来、写出来」的那一半，至少要有一条测试跑真实的生成路径（不 mock 掉生成端）。自检问句：**生产生成这个值的代码坏了，哪条测试会红？**一条都答不出 = 只测了一半，补一条跑真实生成路径的。
5. **不复刻被测逻辑**：测试体抄一遍被测代码再断言自己抄的结果，生产改坏它照样绿。识别特征：删掉被测函数后测试依然绿。
6. **样本量取断言成立的最小值**：断言全是形状检查时，小样本与大样本等价；断言「存在性」的扫面循环，探底后把命中的代表写成显式列表（注释带探针记录），不跑满 N 个赌命中。边界：断言本身就是分布统计时，样本量是语义，保留。
7. **更新期望值时同步 docstring**：断言值和 docstring 写的是同一事实，出现两个版本 = 不加判断硬把测试改绿的现场证据，改测试必查。
8. **改绿之前先判断**：测试红 = 行为和预期不一致，先判断是代码错了还是测试过时了；确认代码是对的才更新测试。

### 删除测试的工序(src 指针对账)

**删除批(尤其整目录删除)必须先做 src 指针对账,再删**:

- 对账对象:src/sr_od 下注释/docstring 里「行为由 test_xxx 钉住」类声明——按将删文件名与测试函数名逐个 `git grep '<名>' -- src/sr_od`(可写临时脚本批量扫,脚本用完即删,不进仓)。
- 处置序:先消费清单——每条指针要么改写出处(指向仍存在的锁),要么随删除批同步摘除/改写 src 注释——然后才删测试;**删完再扫一遍确认零悬空**,并把清单附进删除 commit 说明。
- 背景:2026-09-13 清理提交整目录删除 261 个 CW 测试文件且未做反向对账,一次性打悬 ~60 处 src 声明;本工序即其治根防线。
- **已删测试禁止未经用户裁决恢复**:认为某条已删锁面有覆盖价值 → 先申报覆盖缺口、经裁决后按现行纪律重写为直锁;禁止直接回迁旧文件/旧锁(2026-09-15 CW 严格瘦身轮收口定)。

### 禁止清单（写时禁、评审删）

- **恒真断言与空壳**：`assert X or True`、只 print 不断言、空函数体、永久 skip 的死占位。
- **构造/字段透传断言**：构造对象后逐字段 assert 赋值——这是 dataclass 的行为，不测我们的代码。例外：断言的值本身是跨进程契约（如 analyze_screen 输出里的字段取值，外部消费者按它解析）——判别问句：**这个值改了，谁会坏？**答得出具体消费者才保留。
- **子集断言**：同场景的断言面已被另一条测试完整覆盖，留着的那条取覆盖面更全的。
- **docstring 与断言不符**：docstring 说它防的是 A，实际断言的是 B——自检问句：**这条断言红了，docstring 说的那个故障真的发生了吗？**答不是 = 删或改写。
- **无到期条件的永久 xfail**：要么写明到期条件，要么 `strict=True` 让意外转绿报警；跳过原因（reason）必须与测试体语义一致，不符即装饰器漂移，转绿（XPASS）时摘标复核。
- **无到期条件的迁移对照测试**：为迁移保平安写的「新实现 vs 旧实现结果」对照（旧的一边是捕获的快照或照抄的副本），只在迁移期有意义——它锁的是旧实现的样子，不是设计要的样子；迁移合入后留着，正常迭代一改行为它就误报。写它时必须在 docstring 注明删除时点（如「迁移合入后下一批删」），到点清理：说得出还锁什么核心的按第一原则转正，说不出的一律删。
- **源码扫描，无任何例外**：不在测试里读取/扫描源码做断言——`inspect.getsource` / `read_text` 读 src 下的 .py、AST 解析、标识符/字符串在场断言、调用顺序断言、退役符号墓碑、依赖方向守卫、包布局守卫，一律不写。判别问句：**这条断言红的时候，是哪个运行行为坏了？**答不出 = 违例。架构裁决类防线（分层禁依、退役禁回流）交 review 与代码规范，不进测试网。
- **git 未跟踪的产物当断言锚**：断言依据一律来自测试自造的输入（tmp_path / 合成语料 / monkeypatch 桩）或提交进仓的 fixture；凡**不进 git 跟踪**的本机产物（`.debug/`、本地日志、下载的模型缓存等）一律不作为断言依据。

### 识别类测试的图片输入（真实截图为准）

凡测试识别/检测函数（输入是游戏截图帧的 CV / OCR 解析），输入图**禁止合成**——手画色块只证明「理想图形能过」，检验不出阈值与真实画面的匹配：

- **正常样本**：每个识别函数入库 1 张真实正常帧，断言识别结果 = 人工确认的真值（注释注明来源：哪局 / 哪个画面 / 谁确认）；随重建、改函数逐步补，不预先铺满。
- **故障样本事故驱动**：识别出错的实况帧，每种故障情况补 1 张（修 bug 时把现场帧裁剪入库 + 真值断言）。
- **体积尽量小**：裁到识别所需最小区域；确需多区域联动才保留整帧；webp 无损归档（与主仓模板资产同口径）；入库前看一眼体积。
- **一图一测，聚合断言**：一张图要验的内容（数量 / 分类 / 坐标）在同一个测试里一次读取、一次识别、逐条断言；识别贵（单次秒级），禁多处各自重新读图识别。fixture 落位随现行惯例（域目录根 / `fixtures/` / `screens/<画面名>/`）；缺帧 `pytest.skip` 不 error。

### 单条成本

- 单条目标 <0.5s，容忍 <1s；实测 ≥2s 先想办法便宜化（减样本 / 共享计算 / 换轻 fixture），实在不行才入慢桶并给理由。
- **运行成本要与断言强度匹配**：跑完整局 / 完整流程只为断言一次接线、一个返回类型，属于倒挂——红的时候定位不了，等于用最贵的运行买最弱的断言。判别问句：**把驱动砍到最小，这条断言还成立吗？红的时候我知道先查哪吗？**
- 准入自检四问：**①它红的时候我知道该更新什么吗？②什么真实错误会杀了它？③这条事实是否已有别的测试辖住？④它值多少毫秒？**

## 提交

- 逐文件点名 `git add`（禁 `add -A` / 目录级，防把未纳入本批的文件静默卷进来），提交按阶段拆分（一个功能点 / 一处修复 / 一批文档各一次）。
- 提交后 `git show --stat` 复核：入库面 = 申报面、新增文件在树上、已删文件已出树——自查视角是**提交树**（`git show` / `ls-tree`），不是工作树（工作树可能被 untracked 文件撑出假绿）。

## 运行机制备忘

- OCR 推理设备跟随本地 `config/model.yml` 的 `ocr_use_gpu`：本机开 DirectML 更快；无 GPU 的环境自动回退纯 CPU。注意开 GPU 时与同机其他 DML 进程（实机局 / MCP server）互相争用。
- 排查某个测试要看完整框架日志：设 `SR_TEST_LOG_FILE=1`（见「测试基础设施」）。
- `--durations` 里**第一条测试的 setup 约 2s 是全会话一次性启动成本**（session 级 `test_context`：构造 ctx + 注册全部应用工厂 ~0.6s + OCR 初始化 ~1.0s），只是恰好记在收集顺序第一条的测试头上——不是该测试自身的问题，勿据此排查。
